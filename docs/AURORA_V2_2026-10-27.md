# Aurora V2 — implementation and verification

Base: `12fb367d2ace80b5b2385b5d44ce383d0ca75c70` (main fetched 2026-10-27).

## Scope

Optional Aurora uses the native Appearance selector (`shaah:skin:v1`). Original,
Matrix and Low Stimulation remain available. There is no new account setting,
migration, data transformation or server write for appearance.

Dark blue surfaces, electric blue/violet/pink ambient light, restrained static ring
glow, consistent inputs and shared palette across Today, Work, Log, Social,
Stats, History and Settings. Semantic score/grade colors remain distinct.
Aurora navigation is Today / Work / History / More. Work opens the existing Today
Work control, expanding its mobile disclosure; it does not advance milestones.
More exposes the existing Daily Log, Social, Stats and Settings actions in a
native modal with keyboard focus containment, Escape and focus restoration.
Switching away from Aurora closes that modal and restores native navigation.

The conversation reference exposes approval text but no readable mockup image;
visual implementation follows the user's supplied design description and the
real application rather than claiming pixel comparison against that image.

## Source and CSP audit

Main's entrypoint loaded `assets/app.aurora-20261026.js`, while `source/app.js`
and the builder/tests still represented an older skin implementation. Source is
now aligned with the actual main runtime (only the Aurora description is new),
then built to `assets/app.8849b7d224545c38.js`. Auth, persistence, historical
configuration, scoring and data export/import functions are unchanged.

The existing strict CSP is unchanged: no inline handlers/styles/scripts, eval,
new origins or network dependencies. Optional skin CSS and JS now have SHA-384
SRI, anonymous CORS and content-derived cache keys, refreshed by the builder.
Removed a stray unmatched `</style>` from the actual main entrypoint.
The obsolete standalone floating toggle script is replaced by presentation-only
navigation; the native selector remains the single source of truth.

Test resource routing serves checked-in local assets, including the skin and
fonts. Skin tests exclude scheduled `cfgbak` housekeeping from the appearance
write count; configuration, day data and scores are still compared in full.
